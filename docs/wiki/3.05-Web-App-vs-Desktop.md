# Web App Vs Desktop

This reference enumerates functional differences and limitations of the web app compared with the desktop (Electron) app. Most limitations stem from browser security (CORS, CSP, sandboxing) rather than intentional feature removal.

When the web app is embedded in another Electron application, it retains web app capabilities and limitations. Desktop features require Super Productivity's own desktop app.

## Startup Display

The loading page and initial app shell appear without logo, pulse, or slide-in animations. Android does not show a separate native quick-add button while loading; the regular quick-add button becomes available with the app interface. Browser compatibility errors remain visible when a browser cannot run the app.

## Mobile Matrix Task Previews

The notebook home hides footer metadata, including overdue labels, to keep task rows compact. Dates and status remain available in the task editor and scoped project/tag matrices.

The matrix home page shows only the four quadrants. On phones, both rows share the available space below the calendar. Unclassified tasks remain stored and accessible in task lists; project and tag matrix views retain their unclassified entry.

The home uses a notebook-style header and quadrant cards while retaining the configured background color. The view switch changes between the two-column matrix and a single-column list without changing task order or classification. Colored calendar dots reflect classified tasks scheduled for each date. Open the category heading to access filters and previous/next week controls. Quadrant heading arrows open the full list, where the add button remains available. The home navigation uses notebook icons; its account-shaped button opens the existing actions menu. New installs include the Focus entry. The mobile add button has no mascot or first-task tooltip; adding a task still works normally. The category heading has no HOT badge, and the matrix has no long-press hint sticker.

## Mobile Task Composer

On the notebook home screen, tapping a quadrant's empty space opens the mobile
composer with that quadrant and the selected calendar date. Added child plans
appear in an indented branch and are saved as the new plan's subtasks. The
quadrant picker redraws the selected oval each time it opens; clearing reverses
the drawing before dismissing the picker.

Parent plans use a checklist icon and open an anchored subtask popup with a
full-screen backdrop. Plain plans use a circular arrow. Existing enabled click
counter habits with streak tracking appear in the green quadrant with a lightning
icon; their completion uses the existing dated counter records.

Swipe the date heading or week strip horizontally to move between weeks. Date
progress counts classified parent plans and enabled habits once each, including
completed plans. Archived tasks use their recorded completion day because the
archive clears scheduling fields. The same month calendar opens from the home
date heading, its handle, and the composer's other-date and range controls. It
supports month navigation, lunar visibility, cancel and confirm. Mainland holiday
adjustments and solar terms are supplied for 2026; other years retain lunar dates
and festivals without guessing unpublished holiday adjustments.

Date changes fade the date heading and incoming task rows, including direct day
selection. The quadrant frames stay mounted and do not move during the transition.
Horizontal dragging follows the finger in a separate layer from the incoming
week's slide animation. Reduced-motion preferences disable these transitions.
While the phone composer is open, the obscured home keeps its measured height
and banner size so keyboard changes do not resize the quadrants behind it.
Calendar confirmation inside the composer closes only the
calendar and preserves the draft. Its toolbar aligns icon centers and caption
baselines. The five-entry notebook navigation keeps the same appearance in the
Planner and remains available in Focus. Switching tabs hides the focus view without
cancelling an active session.

The central add button opens a white bottom sheet with Today, Tomorrow and Other date tabs. Its toolbar provides quadrant selection, inline subplans, a time range, repeat rules and opt-in reminders. Daily, Weekly, Monthly and Yearly repeat each offer an interval of 1–1000 cycles and an optional inclusive end date. The selected plan date anchors the interval. Confirm applies the rule; Cancel preserves the previous rule. The Statutory Chinese workdays option skips holidays and includes compensatory weekend workdays using the published 2026 schedule. Generation pauses outside the supported year until the holiday calendar is updated. The notebook composer has no Custom repeat option. Repeat selection uses color transitions and fades without moving the home layout. It has no Inbox tab or assistant decoration. The circular category button opens a list of existing tags (categories) and projects (goals), with actions to create either through the existing dialogs; selecting No category clears both choices.

End dates and statutory workday flags are optional synchronized recurrence fields, so existing saved rules retain their behavior. Older app versions ignore these new limits; devices sharing these rules need the updated app for matching recurrence behavior.

Monthly repeats use the last day of a shorter month when their anchor day does
not exist. Yearly repeats anchored to February 29 use February 28 in non-leap
years and return to February 29 in leap years. Forward previews and daily task
generation use the same date convention, including the inclusive end date.
Changing the plan date revalidates the confirmed repeat window before saving;
an invalid window keeps the draft open for correction, including keyboard submits.

The quadrant picker uses a four-cell coordinate popover. Subplans become ordinary subtasks, and preset recurring plans retain their quadrant and subtask templates for future occurrences. Time and repeat editors apply changes only on Confirm. Timed ranges use the existing planned start and estimate; a multi-day range also sets the existing deadline. All-day ranges do not invent a time estimate. Reminders require a timed start. The desktop composer retains its existing controls, search and short syntax.

Quadrant and subplan drafts survive closing and reopening the composer within the same browser session. If saving subplans is interrupted, Retry continues from the saved parent and remaining children. These drafts are local to the session and are not part of synchronized task data.

## Features Unavailable or Restricted in the Web App

### Plugin System

Plugins that require Node.js execution (elevated permissions) are disabled in the web version. When such a plugin is loaded, the app shows a disabled placeholder with an error stating the plugin requires the desktop version.

Plugins are not strongly sandboxed from the host app on either platform. See
[[2.21-Manage-Plugins]] before installing third-party code.

### Calendar Integration

Calendar providers can be disabled for the web app or Android app via an `isDisabledForWebApp` flag to avoid CORS and WebView failures. When this flag is set and the app runs in a browser or Android WebView, calendar event requests return empty results instead of performing the HTTP request. The UI shows a prominent warning that calendar integration will likely not work in the browser or Android app and recommends downloading the desktop version.

### Local File System

- **Automatic backups to file system:** Available only in Electron (desktop) and Android; not in the web browser.
- **Local file sync:** The web app cannot sync to local or network folders; that sync provider is not available in the browser.

### Time Tracking

In the web version, time tracking only works while the app is open. Idle time tracking in the browser requires the Super Productivity Chrome Extension to be installed. Without the extension there is no idle detection, so a forgotten timer keeps running; while a task is tracked the browser tab title shows the time logged on it today and its name (for example `25m - Write report`), which keeps a running timer visible from a background tab.

### App Updates

The web app updates itself through its service worker and prompts for a reload when a new version is deployed. The desktop app instead checks the GitHub releases API once a day and shows a dismissible notice linking to the download page (configurable via the Misc setting "Automatically check for new versions"; not present on Microsoft Store, Mac App Store, or Snap builds, which update through their stores).

### URL Scheme Actions

The `create-task`/`complete-task` URL scheme actions (see [[3.01-API]]) rely on the app having a registered custom URL scheme, which Electron and the Capacitor iOS and Android builds have. Not available in the web (browser) build.

The same scheme also carries UI actions that just open something: `add-task` (the quick-add bar), `today` and `inbox`. On iOS all three work and are additionally exposed as Home Screen quick actions — long-press the app icon to get New Task, Today and Inbox. On desktop only `add-task` is recognized. On Android none of them are, because `AndroidManifest.xml` declares intent filters only for the task actions; Android also has no launcher shortcuts for the app.

## Browser-Related Limitations

### CORS (Cross-Origin Resource Sharing)

WebDAV sync and calendar integration are likely to fail in the browser due to CORS. The app detects CORS-related failures and can show localized messages suggesting the user check server configuration. The desktop and mobile (iOS/Android) apps issue these requests through a native HTTP layer and are not subject to browser CORS; the web app is. This is why CalDAV calendar sync (e.g. with iCloud) works in the desktop and mobile apps but typically fails in the web app, where the server does not send the required CORS headers.

### WebCrypto API

The web app depends on modern browser support for:

- **Dropbox PKCE authentication:** Requires `window.crypto.getRandomValues` and `window.crypto.subtle.digest`.
- **Secure context:** WebCrypto (e.g. `crypto.subtle`) is only available in secure contexts (HTTPS). The app shows alerts when WebCrypto is unavailable or when run over non-HTTPS.

### Multi-Tab Instance Prevention

The web version uses BroadcastChannel to prevent multiple tabs from running the app at once. If another tab already has the app open, the new tab shows a blocker message asking the user to close one of the tabs.

## Storage, Memory, and Performance

### Browser Storage Persistence

The web app requests persistent storage from the browser. If the request is denied, the user sees a warning that data may be lost. Denial is surfaced via a snack notification.

### Storage Quota Monitoring

The app uses the Storage API to estimate usage and quota. When available space falls to 333 MiB or less, the user is alerted that disk space is low and the app may be affected.

### IndexedDB Quota Exceeded

When IndexedDB quota is exceeded, the app triggers emergency compaction with reduced retention (24 hours instead of 7 days) and uses a circuit breaker to avoid infinite retry loops.

### Service Worker

The web app registers a Service Worker for offline caching (PWA). This is disabled for Electron and Android. Background behavior is limited to what the browser's Service Worker API allows.

## File Size and Upload Limits (Sync)

These limits are enforced by the sync server; they affect web users who sync:

- **Operation payloads:** 20 MB maximum.
- **Compressed operations:** 10 MB maximum.
- **Snapshots:** 30 MB compressed, 100 MB decompressed.
- **WebDAV:** 10 MB maximum for XML responses; 100 MB maximum for file content.

## Offline and Background Processing

### Background Throttling

The desktop app disables background throttling for its window. The web app is subject to the browser's background tab throttling, which can affect timer accuracy and background task execution when the tab is in the background.

On Android, a Focus session's foreground service keeps its timer and task time while the app is in the background. If Android recreates the app screen while that service is still running, the app restores the session and task time. This recovery does not cover Android terminating the entire app process.

### Offline Support

The web app uses a Service Worker (production builds) to cache assets for limited offline use. Full offline behavior is more limited than on desktop and Android. The app shows an offline banner when the network is unavailable.

## Plugin and Integration Limitations (Web)

### Plugin API in Iframes

Iframe plugins receive a filtered `window.PluginAPI` object injected into `index.html`.
The iframe can use the injected task/project/tag APIs, dialog and notification APIs,
navigation helpers, persistence helpers, registration helpers, counters, and action
dispatch. APIs not injected into the iframe are unavailable, even if they exist on the
host-side plugin bridge.

`executeNodeScript()` is proxied through the host bridge for iframe plugins when
the desktop app grants the plugin `nodeExecution` permission. Both built-in and
uploaded plugins may request it. Uploaded plugins receive a native warning that
their identity is unverified and that granting access permits full machine
access.

### Iframe Boundary

Iframe plugins use a supported bridge, but it is not a security boundary:

- The iframe includes `allow-same-origin`, which is required for the packaged
  desktop UI.
- Same-origin iframe code can reach the parent directly. The filtered Plugin
  API `postMessage` bridge is the intended interface, not enforced isolation.
- Inline CSS, JavaScript, and small assets in `index.html` for portable iframe plugins. Arbitrary extra files from uploaded plugin ZIPs are not served to the iframe; external URLs depend on the app/runtime CSP.

### Chrome Extension for Integrations

Jira integration and idle time tracking in the web version require the Super Productivity Chrome Extension to be installed.

For self-hosted Jira instances where the server is configured with appropriate CORS headers, the extension requirement can be bypassed: enable **Fetch Jira directly from the browser (bypass extension)** in the Jira advanced settings. When active, the app sends API requests directly from the browser instead of routing them through the extension. This option has no effect in the desktop app or on Android.

If the Jira API is reachable at a different host than the public issue links (e.g. an internal API endpoint vs. a public URL), set **Alternative host for Jira links** to the public host. That value is used only for constructing browser URLs in task details, not for API calls.

## Native Features Not Available in the Web App

The web version does not have:

- Native file system access (open/save dialogs, automatic backups to disk).
- OS-level notifications (it uses the Web Notifications API instead).
- Window management (minimize to tray, global show/hide, custom title bar).
- System tray integration.
- Global keyboard shortcuts (only in-page shortcuts; desktop can register system-wide shortcuts).

Certain UI elements tied to these features are hidden in the web build via platform-specific CSS or logic.

## Spell Checking

Spell checking (red underlines for misspelled words) is intentionally disabled in the desktop (Electron) app on every operating system. On Windows and Linux, Electron's spellchecker downloads Hunspell dictionaries from Google's CDN by default, which conflicts with the app's offline-first, zero-data-collection approach. On macOS, Electron uses the operating system's native spellchecker instead. The desktop app disables spell checking at startup on all platforms. The setting is reapplied on every launch, which is why editing Electron's internal `Preferences` file to re-enable it does not stick.

The web app is not affected: in the browser, the notes editor uses the browser's own spell checking. Task titles and other short inputs have spell checking turned off on all platforms, a deliberate choice — red squiggles in task titles were repeatedly reported as distracting (issues #2874 and #4040).

Re-enabling spell checking in the desktop app is not currently configurable. On Windows and Linux, avoiding Google's dictionary downloads would require shipping or self-hosting spellcheck dictionaries; macOS uses native spellchecking APIs. If spell checking matters to your workflow, please describe it in an issue.

## Platform-Specific Availability

### Task Completion on Touch Devices

On touch devices, the task context menu omits **Mark as completed** and
**Mark as not completed**. Use the task's completion button to change its status.

### Receive Shared Links and Text on iOS

In the native iOS app, choose **Super Productivity** from another app's share
sheet, review the link or text, and tap **Save**. Each share creates one new
Inbox task when you next open Super Productivity. The supplied title is used
when available; otherwise the title comes from the shared text. The complete
shared content is stored in the task's notes. Task titles are limited to 300
characters and shared text to 100,000 characters.

Capture works offline. Pending shares stay on the device until imported;
they sync as ordinary tasks after import. Photos and file attachments are not
supported. This share extension is part of the native iOS app, not the web app.

### Donation and Contribution Links

The Support Us page and links that can lead to GitHub Sponsors are unavailable in native iOS and macOS desktop builds. They remain available in the web app, native Android, Windows desktop, and Linux desktop builds.

## Documented Error Conditions (Web)

- **CORS errors:** WebDAV (and similar) sync may report CORS failures with localized messages suggesting server configuration checks.
- **WebCrypto unavailable:** Dropbox OAuth and other crypto-dependent features show alerts when WebCrypto is missing or not in a secure context.
- **Storage persistence denied:** A snack notification warns when the browser denies the persistent storage request.
- **Quota exceeded:** The app handles multiple quota-exceeded variants (e.g. Firefox `NS_ERROR_DOM_QUOTA_REACHED`, Safari code 22) and triggers emergency compaction.

## Notes

- The project README describes the web version as "a bit limited" and recommends the desktop version for full functionality, especially for calendar, file system access, and plugin support.
- The Android app offers a "Connectivity-Free Mode" for fully offline use; the web app does not provide an equivalent.
- Some integration features in the browser depend on the Chrome extension to work around security limits.

For installation and download options, see [[2.01-Downloads and Install]]. For sync backends and limitations, see [[2.09-Configure-Sync-Backend]].
